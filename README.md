# MDA Lab — личный кабинет игрока (турниры)

Программа для Windows (Electron): загрузка истории раздач, вкладки статов, сводка по RFI,
матрица рук, реплеер раздач. Сейчас готова вкладка «Открытие (RFI)».

## Что где лежит

- `app/` — сама программа
  - `main.js`, `preload.js` — оболочка Electron
  - `parser/parse.js` — разбор историй раздач (PokerStars и экспорт GG/PokerDom в его формате, Winamax, WPN)
  - `parser/build.js` — потоковая сборка базы и оценка до загрузки; `parser/store.js` — формат базы на диске; `parser/ev-pool.js`, `ev-worker.js` — EV по ядрам
  - `renderer/` — интерфейс: `index.html`, `styles.css`, `app.js` (вкладки, RFI, сводка), `stats.js` (расчёт статов),
    `hands-ui.js` (окно матрицы, список раздач, реплеер), `replay.js` (кадры реплеера)
  - `data/my-base.json` — база героя (109 688 раздач, без имён соперников), старый формат JSON — для разработки и превью
  - `data/my-base-replays.json` — ход раздач-открытий для реплеера
- `tools/build-hero-db.js` — собрать базу из папки с историями раздач (в папку нового формата)
- `tools/convert-base.js` — перевести базу из старого JSON в новый формат без пересборки
- `preview/` — сборка онлайн-превью (`node preview/build.js`)
- `build/installer.nsi`, `build/icon.*` — установщик Windows (NSIS)

## Выбор игрока (шапка)

- Ник в шапке — кнопка со списком: сверху ваши ники (Alias и ник каждого рума), ниже другие игроки базы с числом раздач и поиском.
- Выбор ника выставляет рум в фильтре; смена рума в фильтре возвращает ваш ник этого рума.
- Выбранный соперник ограничивает выборку (`state.player.mask`) — от неё считаются все вкладки, окна матрицы, списки раздач и реплеер.
- **Сейчас соперники демонстрационные** (`buildDemoOpps` в `app.js`): в базе нет имён соперников, каждому отдана часть раздач его рума. Для настоящих данных парсер должен сохранять раздачи соперников; механика выбора останется той же.

## Формат базы и большие объёмы (гигабайты)

- База — папка колонок (`app/parser/store.js`, формат `mdalab-cols-v2`): `meta.json`, по файлу на колонку (`c_<имя>.bin`, Int8/Int16/Int32/Float64), `keys.bin` (хеши раздач для дублей), записи реплеера частями `rp_<n>.dat` с индексом `rp.idx`. Около 230 байт на раздачу вместе с реплеером.
- В окне колонки — типизированные массивы: `c.net[i]` читается как раньше, расчёты вкладок не менялись. Записи реплеера читаются с диска по номерам раздач, только когда нужны.
- Сборка потоковая: раздача → колонки, записи реплеера сразу на диск; файлы и записи zip больше 64 МБ читаются потоком и режутся по границам раздач. Дубли — по 53-битному хешу «номер раздачи|турнир». Порядок — по дате, при равной дате — по порядку файлов; EV считается после сортировки с тем же зерном, что и раньше, параллельно по ядрам (итог не зависит от числа потоков).
- Проверено: на архиве героя (155 МБ) новая сборка совпала со старой во всех колонках, EV и записях реплеера; превью на новом формате совпало со старым во всех 270 снимках вкладок, окон и списков; нагрузочный тест — см. ниже.
- Старая база (`hands.json` + `replays.json`) переводится в новый формат при первом запуске, значения не меняются.
- Нагрузочный тест (2 ядра, 3 ГБ историй: zip 1,5 ГБ на 28 тыс. файлов, один файл 832 МБ, zip с записью 670 МБ): 2 163 690 раздач без потерь и дублей, сумма итогов совпала, база 475 МБ, разбор 200 с (~15 МБ/с на ядро), EV ~1000 с на 2 потоках, пик памяти 676 МБ (~0,3 КБ на раздачу во время сборки; в окне — ~0,1 КБ на раздачу).
- Ориентир на 8-ядерном компьютере: ~3 мин на 1 ГБ историй (разбор ~70 с/ГБ в одном потоке, EV ~95 с/ГБ в 7 потоках). Оценка в окне загрузки на архиве героя ошиблась на 4–8 % (с запасом).
- Загрузка заменяет базу целиком: несколько архивов выбирайте вместе (или папку, где они лежат). Размер архива и файлов внутри не важен — всё читается потоком; zip64 поддерживается.

## Загрузка базы и приватность

- Кнопка «Загрузить базу»: выбор папки, файлов или zip-архивов (читаются без распаковки, `app/parser/zip.js`, поддерживается ZIP64) → программа находит ники героя (по «Dealt to», а для румов без карт героя, как PokerDom, — по игроку, который сидит почти во всех файлах) → пользователь отмечает свои ники, рум и имя Alias → разбор в фоне с прогрессом (`app/import-worker.js`, `app/parser/build.js`).
- База хранится только у пользователя: по умолчанию `%APPDATA%/MDA Lab/base`, или в папке «MDA Lab база» внутри места, которое игрок выбрал в окне загрузки («Где хранить базу» → «Выбрать папку…»; выбор хранится в `%APPDATA%/MDA Lab/config.json`). Своя подпапка — чтобы пересборка и удаление базы не задевали чужие файлы. Кнопка «Удалить базу с компьютера» в окне загрузки.
- До загрузки программа прогоняет образец историй (~16 МБ) и показывает: примерно сколько раздач, сколько места займёт база, сколько свободно на выбранном диске и сколько времени уйдёт на этом компьютере. Если места не хватит — предупреждает и не начинает загрузку.
- Установленная программа стартует пустой. `app/data/my-base*.json` — только для разработки и превью, в установщик не попадают.
- Папку для установщика собирать только так: `node tools/stage.js <electron-win> build/stage` — скрипт не копирует личную базу и останавливается, если в папке нашлись раздачи или ники героя.

## Пересобрать базу из историй раздач

node tools/build-hero-db.js <папка_с_раздачами> app/data/my-base.json

## Решения, согласованные с HUD (Hand2Note)

- Позиции: от баттона CO, HJ, MP; при 5+ местах перед баттоном MP занимает два места; остальные — EP.
- RFI по стеку считается по открытиям не олл-ином (NAI).
- ISO: в колонке BB без блайнда против блайнда, в TOT — все; «/Fold» — фолд героя на лимп-рейз после изолейта.
- Ответ соперников на открытие — по первому действию соперника (19 / 55 / 26 на всей базе).

## Методология расчётов (как в Hand2Note)

Все вкладки считаются по правилам Hand2Note; общая часть живёт в парсере (`app/parser`) и действует для всех вкладок сразу.
Сверено с Hand2Note на базе героя (RFI и колд-колл: руки и факт совпадают, EV — до десятых bb/100).

- **Участники раздачи** — только те, кто поставил анте/блайнд или ходил на префлопе (севший «в ожидании» не считается).
- **Позиции** — назад от BB по участникам: SB, BTN, CO; UTG — первое место, только если за столом сидят все места (стол полный); остальные — MP. HJ и EP нет.
- **Результат** — итог раздачи в BB этой раздачи, без баунти, без округления.
- **EV (all-in adjusted)** — поправка только если после олл-ина торговля закончилась до ривера; каждый банк — по эквити на момент, когда его закрыли олл-ином, и только между претендентами на этот банк (карты остальных из колоды не убираются); префлоп — 20 000 случайных досок.
- **Споты** — по фильтрам Hand2Note «Префлоп действие перед игроком» и «Префлоп»: Unopened, 1 Limper / 2+ Limpers, 1 Raise (ровно один рейз, без лимперов до и коллеров после); линия «C» — колл был единственным ходом героя на префлопе.
- **Всплывающие окна матрицы рук** (наведение и клик: шапка окна, клетки, группы рук, списки раздач) показывают только фактический винрейт, без EV. Цифра в клетке = сумма итогов раздач из её списка ÷ их число; шапка окна = сумма по всем клеткам. EV остаётся только на карточках вкладок.
- Каждую новую вкладку сверять со скриншотом отчёта Hand2Note по той же выборке.
