# MDA Lab — личный кабинет игрока (турниры)

Программа для Windows (Electron): загрузка истории раздач, вкладки статов, сводка по RFI,
матрица рук, реплеер раздач. Сейчас готова вкладка «Открытие (RFI)».

## Что где лежит

- `app/` — сама программа
  - `main.js`, `preload.js` — оболочка Electron
  - `parser/parse.js` — разбор историй раздач (PokerStars и экспорт GG/PokerDom в его формате, Winamax, WPN)
  - `parser/build.js` — потоковая сборка базы и оценка до загрузки; `parser/store.js` — формат базы на диске; `parser/ev-pool.js`, `ev-worker.js` — EV по ядрам
  - `renderer/` — интерфейс: `index.html`, `styles.css`, `app.js` (вкладки, RFI, сводка), `stats.js` (расчёт статов),
    `hands-ui.js` (окно матрицы, список раздач, реплеер), `replay.js` (кадры реплеера)
  - `data/my-base.json` — база героя (109 688 раздач, без имён соперников), старый формат JSON — для разработки и превью
  - `data/my-base-replays.json` — ход раздач-открытий для реплеера
  - `data/demo-base/` — база демо-игрока (не в репозитории: `node tools/build-demo.js`; установщик собирает её сам)
- `tools/make-demo-hh.js` — синтетические турнирные истории для демо (столы, уровни с анте, стили игроков, олл-ины, сайд-поты); `tools/build-demo.js` — демо-база из них обычной сборкой
- `tools/build-hero-db.js` — собрать базу из папки с историями раздач (в папку нового формата)
- `tools/convert-base.js` — перевести базу из старого JSON в новый формат без пересборки
- `preview/` — сборка онлайн-превью (`node preview/build.js`)
- `build/installer.nsi`, `build/icon.*` — установщик Windows (NSIS)

## Алиасы и датамайнинг

- В одной базе может быть несколько алиасов (вы, друг…): у каждого своё имя, свои ники и свои раздачи (колонка `aid` у ваших раздач, `meta.aliases`). Алиасы не смешиваются; в списке игроков в шапке все алиасы сверху, под выбранным — его ники по румам.
- Загрузка: если все найденные ники уже есть в базе — имя не спрашивается, раздачи дописываются в их алиас. Новые ники — поле «Имя Alias» (подставляется заново для каждого архива): другое имя — новый алиас, имя существующего — ники добавятся к нему. Все раздачи одной загрузки идут в выбранный алиас (у GG в экспорте все герои — «Hero»).
- Повторы: ваша раздача — по (раздача, алиас); та же раздача того же ника под другим именем алиаса — тоже повтор. Соперники раздачи пишутся один раз, сколько бы алиасов её ни прислали; ники алиасов в соперники не попадают.
- Датамайнинг (в историях нет ваших карт, ни один ник не отмечен): алиас не создаётся, все игроки раздач идут в «Другие игроки». Точка обзора для реплеера — игрок на BB; рум — по заголовку (PokerStars с временем ET, экспорт GG без него, Winamax, WPN, PokerDom). Раздачи, уже лежащие в базе, пропускаются в обе стороны.

## Редактор алиасов (вкладка «База → Редактор алиасов»)

- Алиас — набор ников: ваши ники (раздачи с вашими картами, `aid` + `nk` у ваших строк), ваши ники из других алиасов (`mine` — любые сочетания своих ников) и игроки базы (`opp` — их строки из «Других игроков»). Статистика алиаса собирается из его ников при выборе (`buildView` в app.js), раздачи не переносятся.
- Убрать свой ник (`off`) — он остаётся под алиасом бледным и открывается отдельно; убрать игрока базы — он возвращается в «Другие игроки» (участники алиасов там не показываются).
- Новый алиас — из любых ников; распустить можно алиас без своих раздач (`gone`, номер aid не переиспользуется). У каждого алиаса рядом с названием — число ников.
- Правки копятся в черновике и применяются кнопкой «ОК» (пишутся в `meta.json` через IPC `aliases:save`, редактор закрывается — возврат на прежнюю вкладку с этим алиасом). В демо — только в памяти. Дозагрузка сохраняет все поля алиасов.

## Демо-игрок

- Кнопка «Посмотреть на демо-данных» открывает `data/demo-base` как обычную базу (только для просмотра, ваша база не трогается): 24 074 раздачи на трёх румах, 149 тыс. строк соперников, реплеер. Загрузка своей базы или перезапуск выходят из демо.

## Выбор игрока (шапка)

- Соперники настоящие: список из базы по числу раздач с поиском по всем игрокам; выбранный соперник загружается как своя база (те же колонки), все вкладки, окна, списки и реплеер (с его места) считаются по его игре. Матрица рук соперника — только по показанным картам.


- Ник в шапке — кнопка со списком: сверху ваши ники (Alias и ник каждого рума), ниже другие игроки базы с числом раздач и поиском.
- Выбор ника выставляет рум в фильтре; смена рума в фильтре возвращает ваш ник этого рума.
- При выборе соперника `DB` переключается на его базу (`loadPlayerDb`), ваша база хранится в `HERO_DB`.

## Формат базы и большие объёмы (гигабайты)

- Формат `mdalab-cols-v3` (`app/parser/ingest.js`, `table.js`, `store.js`): `meta.json`; `g<N>/c_*.bin` — ваши раздачи по дате (колонки Int8/16/32, Float64 + ссылка на запись реплеера и отпечаток раздачи); `g<N>/opp/c_*.bin` — раздачи всех соперников за столом, по игроку и дате (те же колонки + игрок, его место); `g<N>/opp/players.json` — ник, рум, первая строка и число раздач игрока; `rp_<n>.dat` — записи реплеера, одна на раздачу, сжаты deflate-raw, только дописываются.
- Около 1 КБ на вашу раздачу вместе с соперниками и реплеером (на архиве героя: 110 тыс. раздач + 599 тыс. строк соперников = 108 МБ). Базы v2 (только вы) и старый JSON читаются; дописывать можно только в v3.
- Парсер: `parseCtx` — общая разметка раздачи, `playerRec` — запись игрока по одним правилам для вас и соперников (у соперника карты — только показанные). Ваши записи совпадают с прежним парсером байт в байт.
- Загрузка и дозагрузка — одна операция `ingest`: разбор по ядрам (`parse-worker.js`, раздачи принимаются строго в порядке файлов), повторы отсеиваются по отпечаткам раздач в базе, строки пишутся в колонки на диск, новые строки сливаются со старой таблицей потоком в новое поколение `g<N+1>`, EV считается для новых строк по ядрам, затем `meta.json` переключается одной записью — сбой посреди загрузки не портит базу.
- EV: ваши раздачи — зерно = номер раздачи после сортировки (как раньше); соперники — зерно от отпечатка раздачи и места (не зависит от дозагрузок). При дозагрузке EV уже лежащих раздач не пересчитывается. Оценка руки и розыгрыш досок без временных массивов: те же числа (10,2 млн рук и 60 224 EV до бита), в 2,6 раза быстрее.
- Проверено на архиве героя: ваши колонки, EV и записи реплеера = прежней сборке; 198 снимков ваших вкладок = формату v2; 3 000 строк соперников сверены с записями реплеера (позиция, действие, ситуация, итог, карты — 0 расхождений); «половина + дозагрузка половины» = полной сборке (кроме EV 142 ваших старых раздач — шум выборки досок); повторная дозагрузка — 0 новых, все повторы.

## Загрузка базы и приватность

- Кнопка «Загрузить базу»: выбор папки, файлов или zip-архивов, или перетаскивание в любое место окна (путь каждого File берётся в preload через `webUtils.getPathForFile` по одному — FileList через contextBridge приходит пустым) (читаются без распаковки, `app/parser/zip.js`, поддерживается ZIP64) → программа находит ники героя (по «Dealt to», а для румов без карт героя, как PokerDom, — по игроку, который сидит почти во всех файлах) → пользователь отмечает свои ники (рум показан подписью) и, если ники новые, имя Alias → разбор в фоне с прогрессом (`app/import-worker.js`, `app/parser/build.js`).
- База хранится только у пользователя: по умолчанию `%APPDATA%/MDA Lab/base`, или в папке «MDA Lab база» внутри места, которое игрок выбрал в окне загрузки («Где хранить базу» → «Выбрать папку…»; выбор хранится в `%APPDATA%/MDA Lab/config.json`). Своя подпапка — чтобы пересборка и удаление базы не задевали чужие файлы. Кнопка «Удалить базу с компьютера» в окне загрузки.
- До загрузки программа прогоняет образец историй (~16 МБ) и показывает: примерно сколько раздач, сколько места займёт база, сколько свободно на выбранном диске и сколько времени уйдёт на этом компьютере. Если места не хватит — предупреждает и не начинает загрузку.
- Установленная программа стартует пустой. `app/data/my-base*.json` — только для разработки и превью, в установщик не попадают.
- Папку для установщика собирать только так: `node tools/stage.js <electron-win> build/stage` — скрипт не копирует личную базу и останавливается, если в папке нашлись раздачи или ники героя.

## Решения, согласованные с HUD (Hand2Note)

- Позиции: от баттона CO, HJ, MP; при 5+ местах перед баттоном MP занимает два места; остальные — EP.
- RFI по стеку считается по открытиям не олл-ином (NAI).
- ISO: в колонке BB без блайнда против блайнда, в TOT — все; «/Fold» — фолд героя на лимп-рейз после изолейта.
- Ответ соперников на открытие — по первому действию соперника (19 / 55 / 26 на всей базе).

## Методология расчётов (как в Hand2Note)

Все вкладки считаются по правилам Hand2Note; общая часть живёт в парсере (`app/parser`) и действует для всех вкладок сразу.
Сверено с Hand2Note на базе героя (RFI и колд-колл: руки и факт совпадают, EV — до десятых bb/100).

- **Участники раздачи** — только те, кто поставил анте/блайнд или ходил на префлопе (севший «в ожидании» не считается).
- **Позиции** — назад от BB по участникам: SB, BTN, CO; UTG — первое место, только если за столом сидят все места (стол полный); остальные — MP. HJ и EP нет.
- **Результат** — итог раздачи в BB этой раздачи, без баунти, без округления.
- **EV (all-in adjusted)** — поправка только если после олл-ина торговля закончилась до ривера; каждый банк — по эквити на момент, когда его закрыли олл-ином, и только между претендентами на этот банк (карты остальных из колоды не убираются); префлоп — 20 000 случайных досок.
- **Споты** — по фильтрам Hand2Note «Префлоп действие перед игроком» и «Префлоп»: Unopened, 1 Limper / 2+ Limpers, 1 Raise (ровно один рейз, без лимперов до и коллеров после); линия «C» — колл был единственным ходом героя на префлопе.
- **Всплывающие окна матрицы рук** (наведение и клик: шапка окна, клетки, группы рук, списки раздач) показывают только фактический винрейт, без EV. Цифра в клетке = сумма итогов раздач из её списка ÷ их число; шапка окна = сумма по всем клеткам. EV остаётся только на карточках вкладок.
- Каждую новую вкладку сверять со скриншотом отчёта Hand2Note по той же выборке.
