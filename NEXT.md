## 1. Сжатие колонок на диске (ещё не начато)
- Замер на датамайнинге (scratchpad/obs/o3): колонки 81 МБ (73% базы), реплеер 31 МБ. `gzip -1` по колонкам: 82 → 17 МБ (≈ 4,8×).
- План: файл колонки `c_<имя>.z` — порции по 16 384 строки, deflate-raw (можно с перестановкой байтов для i32/f64),
  в конце — индекс смещений порций и подвал (n, строк в порции, размер элемента, число порций, сигнатура).
- Чтение старых `c_<имя>.bin` остаётся (совместимость); выбор по наличию файла.
- Места, которые читают/пишут колонки: `parser/table.js` (ColumnReader, ColumnWriter, mergeColumn, patchColumn — для EV: распаковать, поправить, записать целиком, readRange, readAt),
  `parser/store.js` (colBytes, playersCc, playerCol, replays), `parser/migrate.js` (readCol/writeCol), `parser/ingest.js` (scan, applyEv), `preview/pack-v3.js` (читает c_*.bin напрямую), `tools/audit-ev.js`.
- Временные колонки загрузки (tmp-ingest, SpillColumn) можно оставить несжатыми.

## 2. Двоичная запись реплеера (кодировщик написан, не подключён)

## 3. Обновление старой базы при запуске

- В ingest: если старая база ещё не обновлена (rpz != 2) — сначала обновить, потом дописывать.
