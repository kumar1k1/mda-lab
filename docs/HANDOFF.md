# MDA Lab — передача проекта (04.11.2026)

Документ для ИИ-ассистента, который продолжает работу. Прочитать целиком до первого изменения. Отвечать пользователю **по-русски**.

## 1. Где код

- GitHub: `kumar1k1/mda-lab`, ветка **`main`** — в ней вся работа до версии 0.7.60 (ветка `wip-c5` слита 04.11.2026 после полной проверки `npm run audit`, всё OK).
- Начать: `git clone https://github.com/kumar1k1/mda-lab && cd mda-lab` (ветка `main`).

### Правила работы с ветками (обязательно)

1. **`main` — всегда рабочая версия**: из неё в любой момент можно собрать установщик. Прямо в `main` не работать.
2. **Каждая задача — своя ветка от свежего `main`**: `git checkout main && git pull && git checkout -b wip-<коротко-о-задаче>` (например `wip-4bet-fixes`, `wip-postflop`, `wip-limp`). Одна ветка — одна тема.
3. **После каждого изменения — коммит и `git push -u origin <ветка>`**, рабочее дерево чистое (пользователь проверяет, что всё сохранено).
4. **Слияние в `main` — только после полной проверки** `MDALAB_BASE=<база> npm run audit`, в которой все пункты OK: `git checkout main && git pull && git merge --no-ff <ветка> && git push`. В сообщении слияния — что вошло и что проверка прошла.
5. Если в `main` появились чужие изменения, пока шла работа, — сначала влить `main` в свою ветку (`git merge main`), проверить, потом сливать обратно.
6. **Ветки не удалять без прямой просьбы пользователя** (в том числе слитые). Старые ветки `wip-c5`, `wip-v3cards`, `wip-plurals`, `qwen` целиком входят в `main` (своих коммитов в них нет) — в работу их не брать.
7. Версию программы (`app/package.json`, `build/installer.nsi`) поднимать в той ветке, где появляется новая колонка базы или новая сборка установщика.
- Подписи коммитов — как в истории; после каждого изменения — коммит и `git push`, рабочее дерево чистое.

## 2. Правила пользователя (обязательно)

1. Отвечать по-русски, коротко и по делу; цифры — по базе, не «на глаз».
2. После каждого изменения — коммит и push.
3. Установщик собирать **только по просьбе** пользователя.
4. Перед изменением проверить всё, что оно затрагивает («чтобы изменения не коснулись проекта в плохую сторону»): числа карточек, фильтры, окна, списки раздач, реплеер.
5. Полная проверка (`npm run audit`) — перед слиянием в `main`; во время работы — быстрые проверки (см. §6).
6. Термины пользователя — `docs/terms.md`: «окно первого типа» — «Диапазон» (`showSzMx` / `pinSzMx` / `hoverRange`), «окно второго типа» — итог по рукам (`showHandPop` / `pinHandPop` / `hoverHands`).

8. Нельзя обходить капчу и скрыто собирать данные SharkScope (только официальный API — позже).

## 3. Устройство программы

- `app/` — Electron-программа (`main.js`, `preload.js`, `renderer/`, `parser/`).
- `app/parser/` — разбор историй раздач и база:
  - `parse.js` (разбор), `tbet.js` (всё про 3-бет/4-бет/сквиз по записи раздачи), `ingest.js` (загрузка: `rowVals`, `NEW3B`), `store.js` (`SCHEMA` — колонки базы), `migrate.js` (`MIGRATIONS` + `TYPES_OF` — досчёт новых колонок у старых баз при запуске).
  - **Новая колонка = 5 мест:** `tbet.js` → `parse.js` → `ingest.js` (rowVals и NEW3B) → `store.js` (SCHEMA) → `migrate.js` (MIGRATIONS и TYPES_OF). Старые базы пользователя обновляются сами при запуске — перезагрузка рук не нужна.
- `app/renderer/` — интерфейс. Порядок загрузки скриптов одинаковый в `index.html` и `preview/build.js`:
  `core.js`, `widgets.js`, `sec-filters.js`, `windows.js`, `tab-rfi.js`, `tab-cc.js`, `tab-3bet.js`, `tab-vs3bet.js`, `tab-sqz.js`, `tab-4bet.js`, `app.js`, `hands-ui.js` …
- Вкладки: «Открытие» (tab-rfi), «Колд-колл» (tab-cc), «3-бет» (tab-3bet), «Против 3-бета / сквиза» (tab-vs3bet), «Сквиз» (tab-sqz), «4-бет» (tab-4bet). Остальные — заготовки (`app.js`, список `GROUPS`).
- **Фильтры раздела** (шапка вкладки): `sec-filters.js`. `SEC_TYPES` — тип действия; `secF(tab)` — состояние (S стек, T тип, B банк, P позиция). **`CARD_FILTERS`** — единая таблица «какой фильтр действует на какую карточку» (по ней метки на карточках, «умная» подсветка шапки и проверка `tests/audit/filters-table.js`). Меняете действие фильтра — меняйте и код карточки, и `CARD_FILTERS`, и `docs/filters.md`.
- «Умные» фильтры: наведение на карточку — недействующие фильтры шапки тускнеют (`sec-filters.js`, блок `SF`).
- Прокрутка без мерцания окон: `widgets.js`, блок `SCR` (+ `hoverMuted`).
- EV / факт одним числом — `VAL_MODE`, `valPick`, `valSeg` (`widgets.js`).
- Склонения — `cnt`, `nw`, `nlabOf` (`core.js`).

## 4. Превью (страница в браузере)

- `MDALAB_BASE=<папка базы> node preview/build.js` → `preview/MDA-Lab-preview.html` и `preview/base/*.b64.json`; открыть через локальный сервер (`python3 -m http.server` в `preview/`) или `npm run audit` (сам поднимает сервер на 127.0.0.1:8783).
- Нужна база формата `mdalab-cols-v3` (папка с `meta.json`). Откуда взять:
  - у пользователя на Windows: `%APPDATA%\MDA Lab\base` (папка `userData` программы) — попросить скопировать;
  - или собрать из его историй раздач: `node tools/build-hero-db.js <папка историй> <папка базы>`;
  - старую базу обновить: `node -e "require('./app/parser/migrate.js').run('<папка базы>').then(console.log)"`.
- В репозитории есть `app/data/my-base.json` — старая база для разработки (без полных записей реплеера; для свежих карточек мало).
- Пользователь смотрел превью как опубликованную страницу (artifact) — у нового ассистента своя публикация.

## 5. Установщик Windows (только по просьбе)

1. Поднять версию: `app/package.json` (`version`) и `build/installer.nsi` (`APPVER`, `VIProductVersion`).
2. Скачать Electron **33.4.11 win32-x64** (zip с GitHub releases electron), распаковать и переименовать `electron.exe` в `MDA Lab.exe` (так ждёт `installer.nsi`).
3. **Собрать папку только так:** `node tools/stage.js <папка electron-win> build/stage` — скрипт проставит «MDA Lab» в свойствах exe, соберёт демо-базу и **не положит личную базу** (`app/data/my-base*`).
   (Внимание: установщики 0.7.57–0.7.60 собраны копированием `app/` целиком — в них лишний `app/data/my-base*.json`; в установленной программе он не используется, но в следующий раз — только через `tools/stage.js`.)
4. `cd build && makensis installer.nsi` (NSIS 3; на Linux — пакет `nsis`) → `build/MDA-Lab-Setup-<версия>.exe` (в git не хранится).
